## Quote Calculator (internal tool) — built 2026-08-21
Real build shipped at `quote-calculator/quote-calculator.html` — a single self-contained offline file (React/ReactDOM/Babel embedded inline, ~3.4MB, no server/build/internet required). Open it locally (double-click or `file://`); it is not deployed anywhere and was deliberately superseded away from the earlier "separate small deploy" idea per user direction mid-build ("a downloaded file I can just open when needed").
- [x] Feature scope: per-store delivery minimums (Costco $75 / Sam's $50 / BJ's $50 / Amazon $35 non-Prime, real published thresholds) with a warning on each shopping-list card when under the minimum; deposit/payment schedule (50% at confirmation, 50% at event completion — real policy from user, editable per-quote for approved exceptions). Waste/buffer % and tax exemption intentionally not built.
- [x] In-app price editor ("Edit catalog prices" button) — lets you correct/fill in any item's price at any store directly in the tool, persisted to localStorage as overrides on top of the base catalog, no code editing or re-download needed. Adding an entirely new catalog item/family (not just a price) still requires messaging Claude for a code change.
- [x] Pricing research: real current Amazon + Costco prices filled in where a genuine live listing was found (~35 of ~65 priced line items). Sam's Club/BJ's are null everywhere (no public pricing source exists, confirmed by direct search) — fill those in yourself via the price editor. Costco.com actively blocks automated price checks, so Costco coverage is thinner than Amazon's; a few Costco figures came from third-party warehouse-club price-tracking sites rather than costco.com directly (flagged in the data file's header comment). Anywhere neither store had a confirmed price, it's left `null`/$0.00 on purpose rather than guessed — a placeholder that looks plausible is more dangerous than an obvious $0, since it could slip into a real client quote unnoticed.
- [x] **Business-reality finding, not just a data gap:** Costco's national catering program has shrunk to ~4 standard platters and no longer includes a taco bar, BBQ platter, pasta bar, or continental breakfast package as an orderable item. The 4 matching "Catering" families in the tool are priced null for that reason — if you want real numbers there, they'd need to come from an actual local caterer, not Costco/Amazon.
- [x] Hosting/persistence: single local file, localStorage only, no backend, no sharing — supersedes the earlier "separate small deploy" decision.
- [x] Sam's Club + BJ's real pricing added (2026-08-23) — user compiled their own membership pricing into a spreadsheet (`Sams Club + BJ's prices.xlsx`, 19 sheets) and had it imported directly into the catalog, superseding the "null everywhere, fill in yourself" state from the initial build. Matched on base product name only (ignored size/qty/price text embedded in some sheet titles); BJ's sheet prices were stored with no decimal point (e.g. `$1099`) and were converted to `$10.99` per the user's confirmed rule. Capped every catalog item to a max of 3–4 pack-size options per the user's instruction, which required restructuring two families to the sizes actually available in the spreadsheet: napkins (was 500/1000ct → now 504/660/800ct) and the deli sandwich/catering platter (was serves-24/48 → now serves-12–15/20–25). Added a new "Bulk candy" family under Food (30ct bars, 62oz jar) — user confirmed. Where the spreadsheet had no clean match to an existing pack size, prices were left `null` rather than guessed (lemonade, iced tea, coffee/cocoa service, pretzels, cookies, popcorn, fruit/watermelon trays, ice cream, hot dogs, buns, burger patties — none present in the spreadsheet). Coverage is still partial — only spreadsheet items were filled in, remaining gaps are unchanged from the original null state.
